** Qual nivel de paralelismo?

Tres opcoes foram consideradas:

#+begin_export typst
#v(0.6em)
#+end_export

- *Acoes* (argmax de 4 acoes): descartada -- overhead supera o ganho

#+begin_export typst
#v(0.6em)
#pause
#+end_export

- *Steps* (passos do episodio): descartada -- cada step depende do anterior

#+begin_export typst
#v(0.6em)
#pause
#+end_export

- *Episodios*: *escolhida* -- episodios sao independentes; distribuicao direta via =omp for=

#+begin_export typst
#v(0.6em)
#pause
#+end_export

Mas paralelizar sem sincronizacao nao basta: com $T$ threads e $E$ episodios,
cada thread aprende como se tivesse apenas $E slash T$ episodios.


** Sincronizacao Periodica

Cada thread mantem uma *Q-Table local*, treina um lote de =sync_interval= episodios
e funde os deltas na Q-Table global:

#+begin_export typst
#v(0.5em)
#+end_export

#+begin_export typst
#text(size: 0.68em)[
```c
#pragma omp for schedule(runtime)
for (episode = ep_start; episode < ep_end; episode++)
    run_episode(&local_ql, episode);

#pragma omp for collapse(2)
for (state ...) for (action ...) {
    delta_sum = sum_t(local[t][s][a] - snapshot);
    ql->q_table[state][action] = snapshot + delta_sum / active;
}
```
]
#+end_export

#+begin_export typst
#v(0.3em)
#+end_export

*Merge por delta*: divide pelas threads *ativas* (=active = min(chunk, T)=),
preservando o $alpha$ efetivo quando =chunk_size < T=.


** Heuristicas de sync_interval

Duas estrategias automaticas implementadas em =train()=:

#+begin_export typst
#v(0.8em)
#+end_export

- *sqrt*: =sync_interval = sqrt(N/T)= -- equilibra overhead de barreira e divergencia local (inspirado em limites de regret para SGD paralelo)

#+begin_export typst
#v(0.8em)
#pause
#+end_export

- *statespace*: =sync_interval = L * C= -- cada thread explora todos os estados antes de fundir

#+begin_export typst
#v(0.8em)
#pause
#+end_export

Alem disso, testamos valores fixos: *every10* (=i=10=) e *every1000* (=i=1000=).


** HOGWILD!

Todas as threads leem e escrevem na *mesma Q-Table sem nenhum lock*:

#+begin_export typst
#v(0.5em)
#+end_export

#+begin_export typst
#text(size: 0.72em)[
```c
QLearning local_ql = *ql;
local_ql.rand_seed = seed + tid;
/* q_table aponta para a tabela COMPARTILHADA */

#pragma omp for schedule(runtime)
for (episode = 0; episode < N; episode++)
    run_episode(&local_ql, episode);  /* sem lock */
```
]
#+end_export

#+begin_export typst
#v(0.5em)
#pause
#+end_export

Race conditions sao *intencionais e inofensivas* porque:

- *Esparsidade*: cada episodio visita fracao pequena dos $L times C$ estados
- *Escala*: updates ponderados por $alpha <= 0.1$ -- sobrescrever um e ruido $O(alpha)$
- *Simetria*: ambos os valores concorrentes sao gradientes validos

Ref: Niu et al., *Hogwild!*, NIPS 2011.

- $T <= 20$: =OMP_PLACES=cores=, =OMP_PROC_BIND=close= -- 1 thread por nucleo fisico

- $T = 40$: =OMP_PLACES=threads= -- hyperthreading completo

*Medicao de tempo:*

- Apenas o tempo de =train()= -- exclui alocacao, init e I/O

- Paralelo: =omp_get_wtime()= | Sequencial: =clock_gettime(CLOCK_MONOTONIC)=

- Multiplos blocos de replicacao para estimar variancia do escalonador

** Analise de Cache: interpretacao

*Para $T <= 8$*: hogwild tem LLC-miss *menor* -- Q-Table unica de 3,2 KB fica
estavel em L1/L2. Modos federados tem copias separadas por thread, aumentando o footprint.

#+begin_export typst
#v(0.8em)
#pause
#+end_export

*Para $T >= 16$*: hogwild passa a ter *mais* LLC-miss (36,7%) -- cada escrita invalida
a linha de cache nos demais nucleos (protocolo MESI). Statespace aguenta melhor (23,1%)
pois Q-Tables locais ficam isoladas por mais tempo entre syncs.

** Convergencia: causa da degradacao

Com $T$ threads e $E$ episodios fixos, cada thread treina com $E slash T$ episodios.
Quando $E slash T < E_"min"$ o agente nao aprende.

#+begin_export typst
#v(0.8em)
#pause
#+end_export

- *0% de obstaculos*: todos os modos convergem para poucos threads; degrada com o aumento

- *50% de obstaculos*: nenhuma configuracao paralela convergiu para grids grandes

#+begin_export typst
#v(0.8em)
#pause
#+end_export

Mesmo HOGWILD! (que acumula updates de *todas* as threads) falha com 50% de obstaculos:
race conditions corrompem o aprendizado em ambientes densos.

* Conclusao

** Conclusao

- *Gargalo principal*: divisao de episodios. Com $T$ threads e $E$ fixos,
  cada thread treina com $E slash T$ -- abaixo do limiar, agente nao converge

#+begin_export typst
#v(0.7em)
#+end_export

- *Grid 10x10*: gargalo e coerencia de cache -- LLC-miss explode
  de <1,2% para 23--40% entre $T=8$ e $T=16$

#+begin_export typst
#v(0.7em)
#+end_export

- *HOGWILD!* obteve maior speedup bruto (ate *17x* com 40 threads em 100x100),
  mas nao converge com 50% de obstaculos

#+begin_export typst
#v(0.7em)
#+end_export

- Modos sincronizados com intervalos longos (*every1000*, *statespace*) preservam
  melhor o comportamento de cache entre syncs, mas convergem menos

#+begin_export typst
#v(0.7em)
#+end_export

- Schedule e chunk: *nao sao fatores dominantes* (<2% de impacto no speedup)
