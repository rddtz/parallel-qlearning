* Problema e Algoritmo

** Q-Learning: pathfinding em grid

Agente aprende a navegar de $(0,0)$ até $(L-1, C-1)$ em um grid $L times C$
com obstáculos. Ações: cima, baixo, esquerda, direita.

#+end_export

#+begin_export typst

Após o treinamento, a política ótima é extraída como
$pi(s) = arg max_a Q(s,a)$.

* Paralelização

** Qual nível de paralelismo?

Três opções foram consideradas:

#+begin_export typst
#v(0.6em)
#+end_export

- *Ações* (argmax de 4 ações): descartada -- overhead supera o ganho

#+begin_export typst
#v(0.6em)
#pause
#+end_export

- *Steps* (passos do episódio): descartada -- cada step depende do anterior

#+begin_export typst
#v(0.6em)
#pause
#+end_export

- *Episódios*: *escolhida* -- episódios são independentes; distribuição direta via =omp for=

#+begin_export typst
#v(0.6em)
#pause
#+end_export

Mas paralelizar sem sincronização não basta: com $T$ threads e $E$ episódios,
cada thread aprende como se tivesse apenas $E slash T$ episódios.


** Sincronização Periódica

Cada thread mantém uma *Q-Table local*, treina um lote de =sync_interval= episódios
e funde os deltas na Q-Table global:

#+begin_export typst
#v(0.5em)
#+end_export

#+begin_export typst
#text(size: 0.68em)[
```c
#pragma omp for schedule(runtime)
for (episode = ep_start; episode < ep_end; episode++)
    run_episode(&local_ql, episode);

#pragma omp for collapse(2)
for (state ...) for (action ...) {
    delta_sum = sum_t(local[t][s][a] - snapshot);
    ql->q_table[state][action] = snapshot + delta_sum / active;
}
```
]
#+end_export

#+begin_export typst
#v(0.3em)
#+end_export

*Merge por delta*: divide pelas threads *ativas* (=active = min(chunk, T)=),
preservando o $alpha$ efetivo quando =chunk_size < T=.


** Heurísticas de sync_interval

Duas estratégias automáticas implementadas em =train()=:

#+begin_export typst
#v(0.8em)
#+end_export

- *sqrt*: =sync_interval = sqrt(N/T)= -- equilibra overhead de barreira e divergência local (inspirado em limites de regret para SGD paralelo)

#+begin_export typst
#v(0.8em)
#pause
#+end_export

- *statespace*: =sync_interval = L * C= -- cada thread explora todos os estados antes de fundir

#+begin_export typst
#v(0.8em)
#pause
#+end_export

Além disso, testamos valores fixos: *every10* (=i=10=) e *every1000* (=i=1000=).

** Convergência: causa da degradação

Com $T$ threads e $E$ episódios fixos, cada thread treina com $E slash T$ episódios.
Quando $E slash T < E_"min"$ o agente não aprende.

#+begin_export typst
#v(0.8em)
#pause
#+end_export

- *0% de obstáculos*: todos os modos convergem para poucos threads; degrada com o aumento

- *50% de obstáculos*: nenhuma configuração paralela convergiu para grids grandes

#+begin_export typst
#v(0.8em)
#pause
#+end_export

Mesmo HOGWILD! (que acumula updates de *todas* as threads) falha com 50%
de obstáculos, provavelmente pela perda de "esparsidade".

*Causa raiz: desconto gamma anula o sinal de recompensa*

*O paralelo é pior, mas o problema não é só dele:*

- Sequencial: 7 de 10 seeds também não convergem
- Seeds que convergem no sequencial dependem de uma sequência de exploração "sortuda" da RNG
- No paralelo, os episódios são divididos entre threads e os Q-tables são fundidos — quebrando exatamente essa sequência e tornando a falha universal

* Conclusão

** Conclusão

- *Gargalos principal*: divisão de episódios e miss. Com $T$ threads e $E$ fixos,
  cada thread treina com $E slash T$ -- abaixo do limiar, agente não converge

- *Problemas de memória entre cache*: gargalo é coerência de cache, LLC-miss explode
  de <1,2% para 23-40% após $T=8$

- *HOGWILD!* obteve maior speedup bruto (até *17x* com 40 threads em 100x100),
  mas não converge com 50% de obstáculos

- Modos sincronizados com intervalos longos (*every1000*, *statespace*) preservam
  melhor o comportamento de cache entre syncs, mas convergem menos

- Schedule e chunk: *não são fatores dominantes* (<2% de impacto no speedup)
